# React Bits 风格全站改造与国内精选技术化设计

## 目标

在不引入 React 或第三方动画库的前提下，把 Infighting 从浅色静态博客升级为具有 React Bits 视觉语言的深色技术站：使用高对比深色背景、蓝青色光晕、磨砂玻璃导航与卡片、精细微交互，并提供完整的浅色主题和主题记忆。

首页使用用户提供的蓝黑色抽象图片作为封面。与此同时，调整“国内精选”的抓取与筛选流程，使技术内容明显优先、金融商业内容不再用于补足数量，并始终维持至少四条可发布的国内精选；当天不足时使用上一期仍通过严格技术筛选的内容补位。

## 约束与原则

- 保留现有原生 HTML、CSS、JavaScript 架构和静态部署方式。
- 不引入 React、WebGL、第三方动画库、外部字体或新的运行时依赖。
- `public/` 继续作为唯一发布目录。
- 默认使用深色主题，用户可切换至浅色主题；选择保存在浏览器本地。
- 动效服务于层级与反馈，必须支持移动端和 `prefers-reduced-motion` 降级。
- 国内精选质量优先于当天时效；金融商业内容不得用于凑数。
- 单个抓取源失败不能中断其他来源；不满足发布条件时不得覆盖已有数据。

## 方案选择

采用原生渐进式改造方案：通过 CSS 设计变量、少量独立 JavaScript 和现有语义化 HTML 完成全站升级。

没有选择整体迁移到 React，因为当前站点的内容构建、静态发布和统计逻辑均不依赖组件框架。迁移会扩大变更面并增加构建成本，但不会给本次主题、卡片和标签需求带来必要收益。也不采用仅替换配色的最小改造，因为那无法形成封面、导航、卡片、标签和详情页之间一致的视觉系统。

## 视觉系统

### 主题

深色主题为默认主题，背景接近 `#060010`，使用冷黑、深蓝和低饱和紫色形成层次，以蓝青色作为主强调色。页面背景包含轻微径向光晕和低对比纹理，但不能干扰正文阅读。

浅色主题不是简单的纯白反色，而是使用冷白、浅蓝灰、半透明白色面板和收敛的阴影。两套主题通过同一组语义变量表达背景、表面、边框、文字、强调色、光晕和阴影，组件不得写死只适用于单一主题的颜色。

### 导航

所有页面使用统一的悬浮式磨砂玻璃导航。导航保持当前品牌和四个入口，增加主题切换按钮。当前页面使用发光或填充状态标识，不再依赖普通实色标签。导航在窄屏下保持可访问且不遮挡内容，可换行或压缩品牌副标题。

### 首页封面

在首页主内容顶部加入 Hero 封面，并将用户提供的图片复制为 `public/assets/images/hero-ink.png`。图片采用覆盖式裁切，优先保留右侧蓝色流体主体；左侧叠加深色渐变和磨砂玻璃内容面板，以保证标题可读。

Hero 内容包括站点定位、简短技术介绍、主题标签和指向“每日精选”或“最新文章”的页面内操作。图片加载失败时，容器回退到蓝黑渐变背景，内容与操作仍然可用。现有图片内容不进行生成式修改。

### 卡片与标签

每日精选、文章列表、精选归档、文章详情和关于页使用同一套玻璃表面语言：半透明背景、细微渐变边框、柔和阴影和局部高光。指针设备上允许低成本的跟随高光；触摸设备、低性能布局和减少动态效果模式禁用该效果。

标签统一为 React Bits 风格的交互胶囊。文章元数据中的小标签保持紧凑；标签页中的筛选标签具有更明确的数量徽标、悬停反馈、键盘焦点和发光选中态。筛选仍通过 `tags.html?tag=` 表达，因此刷新、复制链接和浏览器前进后退保持有效。

## 前端架构

### `public/assets/css/style.css`

- 使用根级语义变量定义默认深色主题。
- 使用主题属性覆盖浅色变量。
- 为 Hero、悬浮导航、玻璃卡片、标签、主题按钮和页面标题区域提供组件样式。
- 提供 `backdrop-filter` 不可用时的高不透明度表面回退。
- 在移动端降低背景和悬停效果成本。
- 在 `prefers-reduced-motion: reduce` 下禁用渐入、位移、光晕跟随和弹性反馈。

### `public/assets/js/theme.js`

主题控制器只负责主题状态：

1. 页面初始化时读取保存值。
2. 没有保存值或保存值无效时使用深色主题。
3. 更新根元素的主题属性。
4. 同步主题按钮图标、文字、提示和 `aria-pressed` 状态。
5. 用户切换后写入 `localStorage`。

读取或写入本地存储失败时，控制器静默退回当前会话状态，页面仍保持可操作。脚本从站点自身加载，继续符合当前内容安全策略。

### `public/assets/js/main.js`

现有文章、精选、归档和标签渲染职责保持不变。新增的视觉交互仅负责为可交互玻璃卡片更新局部 CSS 坐标变量，不保存业务状态，也不修改内容结构。动态生成的文章和精选卡片在渲染后同样能够获得交互；事件绑定使用委托或统一初始化，避免重复监听。

### HTML 页面

`index.html`、`tags.html`、`archive.html`、`post.html` 和 `about.html` 统一加入主题脚本、主题按钮及更新后的导航结构。首页额外加入 Hero；其他页面使用紧凑标题区域。所有按钮必须具有明确的可访问名称和可见键盘焦点。

## 国内精选筛选设计

### 分类顺序

每条 RSS/Atom 内容将标题和摘要组合后按以下顺序判断：

1. 命中股票、行情、财报、融资、估值、上市、并购、营收、利润或人事变动等金融商业否决词时直接拒绝。技术公司名或“芯片”“AI”等词不能抵消否决结果。
2. 命中 MCU、RTOS、固件、驱动、嵌入式 Linux、边缘推理、模型部署、硬件接口等核心工程词时进入严格技术候选。
3. 仅命中芯片、机器人、传感器、大模型等宽泛词时，需要与工程动作、开发工具、架构、性能、部署或实现类词共同出现，才进入严格技术候选。
4. 只具有泛科技相关性而没有可辨识技术信息的条目不进入国内最低数量补位池。

筛选结果应保留可解释的分类或分值，便于日志和单元测试判断。排序首先考虑是否为严格技术内容，再考虑技术相关性与发布时间，最终限制为每个分区最多八条。

### 上一期补位

国内当天严格技术候选完成链接去重和近似标题去重后，如果少于四条：

1. 读取现有 `public/assets/js/feed-data.js` 中的上一期国内条目。
2. 使用当前版本的金融否决和严格技术规则重新验证旧条目。
3. 排除与当天候选重复的链接和近似标题。
4. 按原有顺序追加，直到达到四条或旧候选耗尽。

旧条目只用于国内分区最低数量保障，不挤占当天合格内容，也不用于国外分区。旧条目保留原始来源和日期，使用户能够识别其时效。

如果补位后仍不足四条，抓取任务返回失败并保持 `feed-data.js` 与归档文件不变。这样不会发布空的国内分区、数量不足的新快照或为凑数引入金融新闻。

### 抓取与写入

单个源失败时记录来源并继续处理其他源。所有来源处理结束后才进行最终发布校验。只有两个分区的数据结构有效且国内分区达到四条时，才生成当前精选并更新七天归档。链接安全策略、十四天新内容窗口和现有近似标题去重继续生效；上一期补位不受当天十四天窗口限制，但必须重新通过当前严格筛选。

## 异常与降级

- 封面图片不可用：显示蓝黑渐变占位，不隐藏 Hero 内容。
- 浏览器不支持磨砂滤镜：使用不透明度更高的主题表面和普通边框。
- 本地存储不可用：主题切换在当前页面仍生效，不显示错误提示。
- JavaScript 不可用：HTML 内容、导航和 CSS 默认深色主题仍可阅读。
- 单个订阅源失败：继续处理其他来源并在日志中标明失败。
- 国内条目不足四条：不写入任何新的精选或归档数据。
- 已有精选文件无法解析：不使用旧内容补位；只有当天数据自行满足发布条件时才允许写入。

## 测试与验收

### 自动化测试

- 主题控制器默认选择深色，并能应用已保存的合法主题。
- 切换主题会更新根元素、按钮状态和持久化值；存储异常不会中断初始化。
- 金融词与技术词同时出现时，条目仍被拒绝。
- 嵌入式、边缘 AI、固件、驱动和工程实践内容进入严格候选。
- 仅含泛科技名词而无工程信息的内容不能用于最低数量补位。
- 当天严格国内内容优先于上一期内容。
- 上一期内容必须重新通过严格规则，并正确执行链接与近似标题去重。
- 当天加补位内容达到四条时允许发布；仍不足四条时拒绝发布。
- 单个国内来源失败不会丢弃其他来源结果。
- 现有完整测试套件继续通过。

### 视觉验收

- 在桌面和移动视口检查首页、标签页、归档页、文章详情和关于页。
- 深色和浅色主题下正文、次要文字、链接、边框和焦点状态均清晰可辨。
- 刷新页面后主题选择保持一致，默认首次访问为深色。
- Hero 在宽屏和窄屏下保留主要图像区域，文字不与高亮图形冲突。
- 磨砂不可用和减少动态效果条件下，布局与内容仍完整。
- 实际运行一次抓取，抽查国内结果无明显股票、财报、融资或纯商业条目，并确认不足时补位来自上一期合格技术内容。

## 完成标准

当五个页面共享一致的 React Bits 风格视觉、深浅主题切换可靠、首页正确使用指定封面、标签交互与移动端体验完整，并且国内精选在不使用金融商业内容补位的前提下始终满足四条发布门槛，且构建、自动化测试与视觉检查全部通过时，本次改造完成。

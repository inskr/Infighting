# 全站移动端性能与交互优化设计

## 背景与目标

当前站点在手机端的首次打开较慢，主要原因是首页 Hero 使用一张 `6400×3600`、约 4.6 MB 的 PNG，以及各内容页共享加载包含全部文章正文的约 263 KB `posts-data.js`。手机导航中的主题按钮也采用了与其他导航项不同的定位与尺寸。

本次改动要在不更改现有 URL、统计 API、纯静态部署和 GitHub Pages 工作流的前提下：

- 降低全站移动端的初始下载量和渲染开销。
- 让手机主题按钮与导航按钮视觉一致，但保留日月图标。
- 为首页 Hero 图片增加低开销的电影感慢速运镜。
- 在所有页面底部加入对影视飓风的特别鸣谢链接。

## 总体方案

保留现有的 HTML、CSS 和原生 JavaScript 架构，不引入 SPA 或新的构建框架。构建阶段拆分文章索引与正文，并为 Hero 生成响应式图片资源。运行时只让每个页面加载它实际需要的数据与脚本。

## 内容数据拆分

`scripts/build-posts.js` 继续以 `posts/*.md` 为唯一内容源，但输出改为：

- `public/assets/js/posts-index.js`：写入 `window.POSTS`，仅包含 `id`、`title`、`date`、`tags`、`summary` 和 `type`。
- `public/assets/posts/<id>.json`：每篇文章一个文件，包含完整元数据与 Markdown 正文。

首页和标签页只引用 `posts-index.js`。文章页先使用索引定位当前文章及上一篇/下一篇，再通过同源 `fetch` 请求当前 `id` 对应的 JSON。浏览器端只允许现有内容 ID 规则中的 ASCII 字母、数字、下划线和连字符，避免构造路径。

旧的 `posts-data.js` 不再被发布页引用，构建时会移除该生成产物，避免与新数据源并存。

## 图片与首屏加载

首页 Hero 改为 `<picture>`，按手机、平板和桌面宽度提供多个尺寸。优先提供 AVIF 和 WebP，并保留压缩 PNG 作为兼容性兜底。资源最大像素宽度不超过实际展示需求，不再发布 6400 px 原图作为浏览器资源。

Hero 是首页 LCP 候选元素，因此不使用懒加载。它使用明确的宽高或稳定的宽高比、`decoding="async"` 和 `fetchpriority="high"`。文章正文中的图片在 Markdown 渲染后统一补充 `loading="lazy"` 与 `decoding="async"`。

## 脚本与渲染开销

`theme.js` 保持在 CSS 前同步执行，以防止主题闪烁。其他页面脚本使用 `defer` 并按页面精简：

- 首页：文章索引、每日精选、统计、点赞存储、URL 策略、主逻辑与 UI 效果。
- 标签页：文章索引、统计、点赞存储、主逻辑与 UI 效果。
- 文章页：Markdown 与高亮依赖、文章索引、统计、点赞存储、主逻辑与 UI 效果。
- 精选归档页：每日精选数据、URL 策略、主逻辑与 UI 效果。
- 关于页：主逻辑与 UI 效果。

粗指针设备和移动端减少玻璃模糊、多层阴影与背景渐变的开销。现有指针追光保持只在精细指针且用户未请求减少动画时启用。

## 主题按钮与手机导航

主题按钮保留太阳和月亮图标，不增加文字标签。在小于等于 680 px 的导航布局中，取消它的绝对定位与专用留白，将它放入 `nav-actions` 的正常水平排列。

它与导航项共享高度、边框、圆角、背景和间距规则，同时保证至少 `44×44px` 的触控区。导航项总宽度超出时，文字导航区域水平滚动，主题按钮保持在操作区域末尾且不遮挡“关于”。

## Hero 动效

采用已确认的 A 方案“电影感慢速运镜”。Hero 图片使用约 8–10 秒的往返动画，只改变 `transform`，实现轻微缩放与水平漂移。桌面端使用完整幅度，手机端降低缩放和位移幅度。

当 `prefers-reduced-motion: reduce` 生效时，Hero 动画完全关闭并恢复静态图片。动效不依赖 JavaScript，不跟踪触摸或陀螺仪。

## 页脚鸣谢

五个发布页共同使用以下语义：

`© <year> Infighting | 嵌入式与边缘计算开发笔记 · 特别鸣谢：影视飓风`

“影视飓风”链接到 `https://www.ysjf.com/index`，在新标签页打开，并设置 `rel="noopener noreferrer"`。链接颜色使用现有弱化文本体系，悬停和键盘焦点时显示可识别的强调色。

## 错误处理

文章页在以下情况中渲染明确错误卡片，并提供返回文章列表的链接：

- URL 缺少 ID 或 ID 格式不合法。
- ID 不存在于文章索引。
- 正文 JSON 请求返回非成功状态或解析失败。

只有正文成功渲染后才进行代码高亮、表格包装和阅读统计。统计接口失败不阻断正文阅读，继续使用现有降级逻辑。

## 缓存与部署

自托管 Express 对图片、CSS、供应商库和普通 JavaScript 设置可重验证的长缓存；对 HTML、文章索引和文章 JSON 使用较短缓存与 ETag，避免内容更新后长时间停留在旧版。API 继续使用 `no-store`。

GitHub Pages 工作流仍只发布 `public/`，不新增服务端依赖。由 GitHub Pages 控制的响应头不在本次范围内，其性能收益主要来自更小的发布资源和按需加载。

## 测试与验收

自动化测试覆盖：

- 构建生成不含 `content` 的文章索引和每篇独立正文 JSON，并保持 ID 校验与重复 ID 拒绝。
- 首页与标签页不再引用全量正文，关于页和归档页不引用文章索引。
- 文章页按 ID 请求单篇正文，且无效 ID、404 和解析失败都显示错误状态。
- Hero `<picture>` 具有响应式源、固定几何信息和高优先级；发布图片大小与尺寸在预期上限内。
- 手机导航不再绝对定位主题按钮，主题按钮保留可访问名称与触控尺寸。
- Hero 慢速运镜仅使用 `transform`，移动端幅度较小，减少动画媒体查询下动画关闭。
- 所有发布页都包含正确的影视飓风链接与安全属性。
- 自托管静态响应使用按资源类型区分的缓存策略，API 仍为 `no-store`。

完成后运行完整 `npm test` 和 `npm run build`，并以手机宽度检查首页、标签、归档、文章与关于页。手动验收时确认主题切换不遮挡导航、Hero 不产生显著布局偏移、单篇正文按需请求，以及鸣谢链接可用。

## 非目标

- 不迁移到 React、Vue、Vite 或其他站点框架。
- 不更改文章 URL、标签 URL、每日精选逻辑或统计 API。
- 不使用触摸跟踪、陀螺仪或高频 JavaScript 动画。
- 不保证由 GitHub Pages 控制的 CDN 缓存头具体值。

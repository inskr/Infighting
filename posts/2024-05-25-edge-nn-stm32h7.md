这个项目的目标是证明一件事：**神经网络推理不是高端芯片的专利，一颗 Cortex-M7 也能做边缘视觉识别**。最终系统在 STM32H743 上实现了摄像头图像的实时分类。

## 系统组成

- **主控**：STM32H743IITx（480MHz Cortex-M7，2MB FLASH，1MB SRAM）
- **采集**：OV7670 摄像头（QVGA 320×240）
- **显示**：LCD 触摸屏实时显示识别结果
- **扩展**：SDRAM 扩展存储（存放帧缓冲与模型中间特征图）

## 零拷贝图像采集

OV7670 的数据流如果让 CPU 逐字节搬运，帧率会惨不忍睹。正确姿势是 **DCMI + DMA**：

```c
void camera_start_capture(uint8_t *frame_buf)
{
    // DCMI 接收像素，DMA 直接搬到 SDRAM 帧缓冲，CPU 完全不参与
    HAL_DCMI_Start_DMA(&hdcmi, DCMI_MODE_CONTINUOUS,
                       (uint32_t)frame_buf, FRAME_SIZE / 4);
}
```

配合 DMA 双缓冲，一帧搬运的同时 CPU 处理上一帧，实现真正的并行：

```c
void HAL_DCMI_FrameEventCallback(DCMI_HandleTypeDef *hdcmi)
{
    frame_ready = true;  // 仅置标志，推理在任务里做
}
```

> **核心思想**：充分利用 DMA 控制器、硬件加速器和中断系统，让数据"自己流"，CPU 只做计算。

## 模型部署：FLASH 不够怎么办

量化后的 int8 模型约 800KB，加上特征图，内部存储明显不够。策略：

1. **权重放内部 FLASH**（只读，XIP 直接执行读取）
2. **特征图与工作区放 SDRAM**（通过 FMC 挂载）
3. **激活值复用内存池**，避免碎片化

```c
// 链接脚本中将模型权重段定位到 FLASH
__attribute__((section(".model_weights")))
const int8_t model_weights[800 * 1024] = { ... };

// 工作区指向 SDRAM
#define WORK_ARENA_ADDR 0xC0000000
```

## 推理优化

- **算子融合**：Conv + BN + ReLU 融合为单算子，减少中间张量
- **CMSIS-NN**：卷积用 `arm_convolve_s8`，利用 M 核的 SIMD 指令
- **输入降采样**：320×240 → 96×96，精度损失可接受，算力需求降 8 倍

最终单次推理约 180ms，配合 DMA 流水线，系统达到约 5fps 的端到端识别速度，满足演示场景需求。

## 拓展板设计

为提高稳定性，我设计了主板扩展板，将摄像头和触摸屏集成到同一核心板上，FPC 排线替代杜邦线，通信故障率显著下降。这也让我完整走了一遍"原理图 → PCB 两层板 → 焊接调试"的流程。

## 结语

边缘 AI 的精髓不在于模型多大，而在于**在算力、内存、功耗的紧约束下把系统跑起来**。这个项目中 DMA 零拷贝和内存分层规划的经验，对我理解更高端的 RK3588 NPU 开发也有很大帮助。
